## Run exit recording

The VM exit observer no longer skips the run's record when it cannot remove
its endpoints. It releases its allocations, removes its endpoints, then writes
the run's exit code, reason and detail, and marks the sandbox `Stopped` only
when both the record and the endpoint removal succeeded. Each exit write is
attempted up to three times and every failure is logged as `VM exit catalog
write failed` with the run id and error.

SDK reconciliation and lifecycle maintenance now also finish a `Starting` or
`Running` sandbox that has no active run once they hold its lifecycle lock: they
remove its endpoints and mark it `Stopped` when its run recorded an exit, or
`Crashed` otherwise. Kill waits for the lifecycle lock before marking a sandbox
`Stopped` on every platform.

## Unrecorded exits

Dead-runtime cleanup only terminates a run that is still `Running`, so it never
replaces an exit the runtime recorded. A run it terminates gets the
`termination_detail` `runtime exited without recording its exit`.

A graceful stop whose run has that detail and no exit code fails with
`Error::SandboxExitUnrecorded` in Rust and `ErrSandboxExitUnrecorded` in Go,
instead of the runtime error `did not confirm clean shutdown`. The VM has stopped
and its runtime is released, but a clean guest shutdown is not confirmed.
TypeScript keeps `RuntimeError`, and Python and Ruby keep their base error.

## Runtime and SDK deployment

Deploy the runtime tag `v0.7.13-gitii.5` together with the Go SDK module tag
`sdk/go/v0.7.13-gitii.5`. The fork module is
`github.com/gitii-labs/microsandbox/sdk/go`; its declared import path remains
`github.com/superradcompany/microsandbox/sdk/go`. Go callers that matched this
stop failure as `ErrInternal` now receive `ErrSandboxExitUnrecorded`.

Older SDKs leave a `Running` sandbox whose runtime recorded its run but could
not remove its endpoints in place until an SDK or maintenance from this
release reaps it. See `COMPATIBILITY.md`.
